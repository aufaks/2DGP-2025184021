# 소닉 애니메이션 뷰어 개발 PRD

## 1. 문서 목적

이 문서는 `PRE_PRD.md`에 기록된 요구사항을 실행 가능한 제품 요구사항과 단계별 개발 계획으로 구체화한다. 각 단계는 독립적으로 확인하고 필요하면 커밋할 수 있는 크기로 나눈다.

## 2. 제품 개요

- 제품명: 소닉 애니메이션 뷰어
- 목적: 제공된 스프라이트 시트에서 소닉의 동작 프레임을 표시하고, 동작별 재생과 반복 순서를 확인할 수 있는 데스크톱 뷰어를 만든다.
- 개발 언어 및 라이브러리: Python, pico2d
- 실행 파일: `sonic_animation_viewer.py`
- 입력 에셋: 같은 디렉터리의 `sonic-sprite.png`
- 배포 형태: 별도 모듈 파일 없이 실행 파일 하나로 구현

## 3. 대상 사용자 및 사용 시나리오

대상 사용자는 스프라이트 기반 애니메이션의 프레임 구성과 재생을 확인하려는 개발자 또는 수업 참여자다.

기본 시나리오:

1. 사용자가 `sonic_animation_viewer.py`를 실행한다.
2. 뷰어가 스프라이트 시트에서 식별한 동작들을 정해진 순서로 재생한다.
3. 걷기, 달리기, 대시, 구르기 동작은 애니메이션과 함께 화면에서 이동한다.
4. 각 동작은 5회 재생되고, 다음 동작으로 넘어가기 전에 1초간 쉰다.
5. 마지막 동작이 끝나면 첫 동작부터 같은 순서를 무한 반복한다.
6. 사용자가 창을 닫으면 프로그램이 정상 종료된다.

## 4. 기능 요구사항

### FR-1. 스프라이트 시트 사용

- `sonic-sprite.png`를 pico2d로 로드해 애니메이션에 사용한다.
- 시트의 제목, 설명, 크레딧 등 캐릭터 프레임이 아닌 영역은 애니메이션 프레임으로 표시하지 않는다.
- 실제 이미지 구조를 확인해 동작별 프레임의 위치와 순서를 정의한다.
- 원본 프레임의 투명 영역과 비율을 가능한 한 보존한다.

### FR-2. 동작 애니메이션

- 시트에서 구분 가능한 모든 소닉 동작을 뷰어가 재생한다.
- 동작별 프레임은 자연스러운 순서로 재생한다.
- 프레임 전환은 시간 기반으로 처리해 실행 환경에 따라 재생 속도가 크게 달라지지 않게 한다.
- 각 동작의 재생 횟수는 정확히 5회다.

### FR-3. 이동 애니메이션

- 걷기, 달리기, 대시, 구르기 등 이동을 표현하는 동작은 프레임 재생과 동시에 캐릭터의 화면 좌표를 갱신한다.
- 이동 속도는 경과 시간에 비례하며, 기본 속도는 걷기 70px/s, 달리기 150px/s, 대시 180px/s, 구르기 120px/s다.
- 이동 동작이 아닌 포즈·표정 애니메이션과 동작 사이의 1초 대기 중에는 캐릭터 위치를 유지한다.
- 캐릭터가 화면 오른쪽 경계를 완전히 벗어나면 왼쪽에서 다시 나타나도록 순환시킨다.

### FR-4. 동작 간 대기 및 순환

- 한 동작의 5회 재생이 끝나면 다음 동작 전에 1초간 대기한다.
- 모든 동작은 정해진 순서로 한 번씩 완료된 뒤 첫 동작으로 돌아간다.
- 전체 동작 순환은 프로그램이 종료될 때까지 무한 반복한다.

### FR-5. 화면 표시

- 캐릭터 프레임을 원본보다 확대해 화면에서 쉽게 식별할 수 있도록 표시한다.
- 확대 시 종횡비를 유지하고 프레임이 화면 밖으로 잘리지 않게 한다.
- 검은색 또는 투명 배경에서 캐릭터가 충분히 구분되는지 확인한다.
- 창의 크기와 배경색은 구현 단계에서 화면 가독성을 기준으로 결정한다.

### FR-6. 실행과 종료

- 파일을 직접 실행하면 뷰어가 시작된다.
- pico2d 이벤트 처리를 통해 창 닫기 요청에 정상적으로 응답하고 리소스를 정리한다.
- 추가 설정 파일이나 별도 Python 소스 파일을 요구하지 않는다.

## 5. 비기능 요구사항 및 제약

- 애니메이션 구현은 Python과 pico2d를 사용한다.
- 애플리케이션 코드는 `sonic_animation_viewer.py` 한 파일에 둔다.
- 스프라이트 에셋은 제공된 `sonic-sprite.png`를 사용하며, 이미지를 수정하거나 재배포하는 작업은 범위에 포함하지 않는다.
- 코드 구조는 동작별 프레임 정의, 재생 상태, 그리기, 이벤트 처리를 구분해 학습 및 수정이 가능하도록 한다.
- 중간 단계마다 실행 가능 상태를 유지하고, 각 단계의 검증이 끝난 뒤 커밋할 수 있어야 한다.

## 6. 범위 제외

- 키보드로 동작을 선택하거나 재생을 제어하는 기능
- 동작별 설정을 외부 파일에서 읽는 기능
- 스프라이트 시트 편집기 또는 자동 프레임 추출 도구
- 동작 재생 영상이나 GIF로 내보내는 기능
- 프로젝트를 여러 Python 모듈로 분리하는 작업

## 8. 단계별 개발 및 커밋 계획

각 단계는 완료 후 실행 또는 코드 검토로 확인하고, 통과한 변경만 커밋한다. 커밋 메시지는 단계의 실제 변경 내용을 반영해 한글로 작성한다.

1. **작업 경로 확인**: `Labs/LEC09`와 입력 이미지의 경로를 확인한다. 검증: 파일이 지정 위치에 존재한다.
2. **실행 환경 확인**: Python 버전과 pico2d 설치 및 실행 가능 여부를 확인한다. 검증: pico2d 가져오기가 성공한다.
3. **빈 실행 파일 생성**: `sonic_animation_viewer.py`를 만들고 최소 실행 진입점을 둔다. 검증: 구문 오류 없이 실행된다.
4. **pico2d 창 초기화**: 창 열기와 종료 처리를 연결한다. 검증: 창이 열리고 닫힌다.
5. **이벤트 루프 구성**: 프레임별 이벤트 처리 구조를 추가한다. 검증: 창이 응답 상태를 유지한다.
6. **그리기 루프 구성**: 화면 지우기, 화면 갱신, 프레임 제한을 연결한다. 검증: 빈 화면이 안정적으로 갱신된다.
7. **이미지 로드**: `sonic-sprite.png`를 로드한다. 검증: 경로 오류 없이 이미지 객체가 생성된다.
8. **스프라이트 시트 크기 파악**: 이미지 전체 크기와 투명 여부를 확인한다. 검증: 소스 영역 좌표 기준을 기록한다.
9. **동작 영역 조사**: 캐릭터 프레임과 제목·크레딧 영역을 구분한다. 검증: 사용할 동작 후보 목록을 정리한다.
10. **동작 목록 확정**: 표시 대상 동작과 재생 순서를 정한다. 검증: 모든 프레임 영역이 어느 동작에 속하는지 설명할 수 있다.
11. **첫 프레임 표시**: 한 프레임의 소스 영역을 잘라 화면에 표시한다. 검증: 캐릭터만 표시되고 잘림이 없다.
12. **확대 배율 적용**: 크기와 위치를 조정한다. 검증: 비율이 유지되고 캐릭터가 화면에서 쉽게 식별된다.
13. **프레임 데이터 구조화**: 동작별 프레임 좌표를 한 파일 안에서 관리한다. 검증: 프레임을 순서대로 조회할 수 있다.
14. **단일 동작 애니메이션**: 한 동작의 프레임을 시간에 따라 바꾼다. 검증: 프레임이 의도한 순서와 속도로 변한다.
15. **프레임 시간 처리**: 시간 경과에 따른 프레임 진행을 적용한다. 검증: 프레임 속도가 실행 루프 속도에 종속되지 않는다.
16. **동작별 반복 횟수 처리**: 현재 동작의 완료 횟수를 센다. 검증: 한 동작이 정확히 5회 재생된다.
17. **동작 간 1초 대기**: 재생 완료 뒤 대기 상태를 추가한다. 검증: 다음 동작 시작까지 약 1초가 걸린다.
18. **다음 동작 전환**: 동작 목록의 다음 항목으로 이동한다. 검증: 목록 순서대로 다음 동작이 시작된다.
19. **전체 순환 처리**: 마지막 동작 뒤 첫 동작으로 돌아간다. 검증: 두 바퀴 이상 연속 재생된다.
20. **전체 동작 데이터 입력**: 확정한 모든 동작의 프레임 영역을 등록한다. 검증: 각 동작이 독립적으로 재생된다.
21. **이동 동작 분류**: 걷기·달리기·대시·구르기와 제자리 동작을 구분한다. 검증: 각 동작에 이동 여부가 지정되어 있다.
22. **동작별 이동 속도 지정**: 이동 동작에 초당 픽셀 속도를 지정한다. 검증: 걷기·달리기·대시·구르기 속도가 각각 정의되어 있다.
23. **시간 기반 위치 갱신**: 재생 중 경과 시간과 속도로 X좌표를 갱신한다. 검증: 같은 경과 시간에는 프레임 루프 횟수와 관계없이 이동 거리가 같다.
24. **화면 경계 순환**: 캐릭터가 화면 오른쪽을 완전히 벗어나면 왼쪽으로 보낸다. 검증: 이동 중 화면 밖에 영구히 남지 않는다.
25. **화면 배치 조정**: 창 크기, 배경, 캐릭터 위치를 다듬는다. 검증: 모든 동작이 화면 안에서 잘 보인다.
26. **종료 및 리소스 정리**: 종료 경로에서 이미지와 pico2d 리소스를 정리한다. 검증: 정상 종료되고 종료 관련 오류가 없다.
27. **이동 동작 검증**: 이동·제자리·대기 상태의 좌표 변화를 검사한다. 검증: 이동 동작만 움직이고 대기 중에는 멈춘다.
28. **수용 기준 점검**: 위 수용 기준을 실제 실행으로 확인한다. 검증: 미충족 항목과 수정 사항을 기록한다.
29. **최종 정리 및 커밋**: 불필요한 임시 코드를 제거하고 최종 상태를 확인한다. 검증: 단일 파일 제약, 동작 반복, 위치 이동을 재확인한다.

## 9. 확인이 필요한 구현 세부사항

- 스프라이트 시트는 여러 동작 프레임과 장식 문구가 한 이미지에 배치되어 있다. 따라서 실제 프레임 경계와 동작 분류는 8~10단계에서 확인한 뒤 확정한다.
- 원본 요구사항에는 창 크기, 배경색, 프레임 재생 속도, 동작 순서가 지정되어 있지 않다. 초기 구현에서는 화면 가독성과 자연스러운 재생을 기준으로 정하고, 검증 중 조정한다.
- pico2d 설치 또는 실행 환경 문제는 애플리케이션 코드와 구분해 기록한다.
